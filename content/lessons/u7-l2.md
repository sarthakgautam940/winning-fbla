Before an AI system can reason, it needs something to reason about: facts and relationships stored in a form a program can use. This lesson covers the main ways of representing knowledge, from semantic networks and frames to ontologies and the knowledge graphs behind search engines, plus the web standards that let machines share meaning. Expect definition questions on the vocabulary, "which representation fits?" scenarios, and questions that read a small graph or a set of triples.

## What knowledge representation and reasoning means

**Knowledge representation** is the part of AI that stores information about the world in a form a computer can use to reason: to answer questions, solve problems, and draw new conclusions. **Reasoning** is the set of methods that use those representations to do the work. The field is often called **knowledge representation and reasoning** (KR&R).

AI4K12 puts the relationship simply: representations are data structures, and reasoning methods are algorithms. The two depend on each other, since a representation is only useful if some algorithm can reason with it, and "knowing" something means being able to both represent it and reason with it.

AI4K12 also divides representations into two major kinds:

- **Symbolic** representations use human-readable symbols, such as logic statements, IF-THEN rules, and labeled graphs, and they are reasoned with by logical inference. "A robin is a bird" stored as a link between two named concepts is symbolic.
- **Numerical** representations use vectors of numbers, such as embeddings (lesson 6.5) and neural network weights, and they are reasoned with by mathematical functions. "Robin" stored as a list of numbers near the list for "sparrow" is numerical.

Symbolic knowledge is precise and easy to inspect and explain, but people must build it by hand, and it breaks on cases nobody anticipated. Numerical knowledge is learned from data and captures fuzzy similarity well, but it is hard to read or explain. The rest of this lesson covers the classic symbolic forms.

## Semantic networks and inheritance

A **semantic network** represents knowledge as a graph: nodes stand for concepts, and labeled edges stand for the relationships between them, such as **is-a** (a robin is a bird), **has** (a bird has feathers), and **can** (a bird can fly).

```figure
type: graph
caption: A small semantic network. Robins and penguins inherit "has feathers" from Bird through is-a links, while a specific "cannot" link overrides the inherited ability to fly for penguins.
nodes:
  - { id: animal, label: Animal, x: 50, y: 10 }
  - { id: bird, label: Bird, x: 50, y: 45 }
  - { id: feathers, label: Feathers, x: 12, y: 45 }
  - { id: fly, label: Flying, x: 88, y: 45 }
  - { id: robin, label: Robin, x: 28, y: 85 }
  - { id: penguin, label: Penguin, x: 72, y: 85 }
edges:
  - { from: bird, to: animal, label: is-a }
  - { from: bird, to: feathers, label: has }
  - { from: bird, to: fly, label: can }
  - { from: robin, to: bird, label: is-a }
  - { from: penguin, to: bird, label: is-a }
  - { from: penguin, to: fly, label: cannot }
```

The power of the is-a link is **inheritance**: properties of a general concept pass down to the more specific concepts beneath it. The network never stores "robins have feathers," but it can conclude it, because a robin is a bird and birds have feathers. Storing each fact once, at the most general level where it holds, saves enormous effort.

Inherited properties act as **defaults** that a more specific fact can override. Birds can fly, but the network stores "penguins cannot fly" at the penguin node, and the specific fact wins. The is-a links also form a **taxonomy**, a hierarchy of categories that can be drawn as a tree, with the most general concept at the **root**, **parent** and **child** categories below it, and the most specific categories, which have no children, as the **leaves**.

## Frames and production rules

A **frame**, also called a **schema**, is a structured record that describes a concept or a situation. Each frame has **slots**, the attributes, and **fillers**, the values in them. Slots can hold default values, and a frame can inherit slots from a more general frame, just as concepts inherit properties in a semantic network.

| Slot | Filler |
|---|---|
| Is a kind of | Food establishment |
| Name | Harbor Street Grill |
| Cuisine | Italian |
| Price range | Moderate |
| Opening hours | Monday to Saturday, 11:00 to 22:00 |

This frame describes one restaurant: "cuisine" is a slot, and "Italian" is its filler. The same idea runs the modern web. Schema.org, founded by Google, Microsoft, Yahoo, and Yandex, publishes shared schemas for structured data, including a Restaurant type that inherits from a more general food-establishment type, and websites use them to mark up their pages so that search engines can understand them.

A **production rule** stores knowledge as a condition and a consequence: IF a condition holds, THEN take an action or draw a conclusion.

```text
IF an animal has feathers AND lays eggs THEN it is a bird
IF an order total is over $50 THEN shipping is free
```

A **production system** combines a set of such rules with a working memory of current facts and an inference engine that decides which rules to apply. Rules are the heart of expert systems, and lesson 7.5 shows how an inference engine chains them together.

## Ontologies

An **ontology** is a formal specification of the concepts in a domain, their properties, and the relationships among them, often with rules that constrain them, so that people and programs share exactly the same meanings. A medical ontology, for example, defines diseases, symptoms, and treatments, along with relationships such as "has symptom" and "is treated by."

An ontology is richer than a taxonomy:

| | Taxonomy | Ontology |
|---|---|---|
| Relationships | Only is-a (parent and child) | Many kinds: is-a, part of, located in, treats, employed by |
| Properties and rules | Usually none | Properties of each concept, plus constraints and rules |
| What a program can do | Look up categories | Check data for consistency and infer new facts |

Ontologies describe **classes** (kinds of things, such as Teacher), **properties** (relationships and attributes, such as employer), and **individuals** (specific things, such as Ms. Park). Their rules let a program infer facts that were never stored. If the ontology says every Teacher is an Employee and every Employee has an employer, and the data says Ms. Park is a Teacher, a reasoner concludes that Ms. Park is an Employee with an employer.

## Knowledge graphs and triples

A **knowledge graph** is a network of real-world entities, such as people, places, organizations, products, and concepts, connected by labeled relationships, usually organized by an ontology so that programs can query it and reason over it. Each fact is a **triple** with three parts:

- a **subject**, the thing the statement is about;
- a **predicate**, the relationship;
- an **object**, the value or entity it points to.

The triple (Ava, memberOf, Robotics) says that Ava is a member of the Robotics club. In the graph, Ava and Robotics are nodes, and memberOf is the labeled edge between them. These triples come from the course's sample school database:

```figure
type: graph
caption: A small knowledge graph built from the sample school database. Every edge is one triple, such as (Robotics, advisedBy, Ms. Park).
nodes:
  - { id: ava, label: Ava, x: 12, y: 18 }
  - { id: dev, label: Dev, x: 12, y: 48 }
  - { id: chloe, label: Chloe, x: 12, y: 82 }
  - { id: robotics, label: Robotics, x: 50, y: 33 }
  - { id: debate, label: Debate, x: 50, y: 82 }
  - { id: park, label: Ms. Park, x: 88, y: 33 }
  - { id: reyes, label: Mr. Reyes, x: 88, y: 82 }
edges:
  - { from: ava, to: robotics, label: memberOf }
  - { from: dev, to: robotics, label: memberOf }
  - { from: chloe, to: debate, label: memberOf }
  - { from: robotics, to: park, label: advisedBy }
  - { from: debate, to: reyes, label: advisedBy }
```

Knowledge graphs shine at questions that chain relationships, called **multi-hop** queries. To find who advises Chloe's club, follow two edges: Chloe is a member of Debate, and Debate is advised by Mr. Reyes. In a table-based database, the same question takes a join (lesson 4.4); in a graph, it is a walk along the links.

The best-known example is Google's Knowledge Graph, introduced in May 2012 under the slogan "things, not strings": instead of matching the characters a user types, search would understand the real-world entities the words refer to. At launch it held more than 500 million objects and more than 3.5 billion facts. Knowledge graphs also power recommendations, question answering, and fraud detection, where accounts that share phones, addresses, or devices form suspicious clusters of links.

## The semantic web: RDF, OWL, SPARQL [Competitive]

The **Semantic Web** is an extension of the World Wide Web in which data is published in standard, machine-readable formats with defined meaning, so that software can find, combine, and reason over information from many sites. Tim Berners-Lee, James Hendler, and Ora Lassila described the vision in a May 2001 Scientific American article. Three World Wide Web Consortium (W3C) standards make it work:

| Standard | Full name | Its job |
|---|---|---|
| **RDF** | Resource Description Framework | The data model: every statement is a subject-predicate-object triple, and an RDF graph is a set of triples |
| **OWL** | Web Ontology Language | Defines ontologies, with classes, properties, and individuals, so programs can infer facts (first published in 2004) |
| **SPARQL** | SPARQL Protocol and RDF Query Language | The query language for RDF data (a W3C standard since 2008) |

SPARQL plays the role for graphs that SQL plays for tables. A query describes a pattern of triples with variables, marked with question marks, and the engine finds every match:

```text
SELECT ?advisor WHERE {
  :Chloe :memberOf  ?club .
  ?club  :advisedBy ?advisor .
}
```

On the school graph, this two-hop pattern returns Mr. Reyes. Schema.org markup on ordinary web pages is the Semantic Web's most widespread success: it is how search engines learn that a page describes a restaurant, a recipe, or an event.

:::tip
**Test tip.** Match the standard to its verb: RDF *models* data as triples, OWL *defines* ontologies, and SPARQL *queries* the data.
:::

:::takeaways
- Knowledge representation stores information about the world in a form a computer can reason with; reasoning methods are the algorithms that use it. Symbolic representations (rules, logic, labeled graphs) are readable but hand-built; numerical ones (embeddings, network weights) are learned but hard to explain.
- A semantic network links concepts with labeled edges (is-a, has, can). Inheritance passes properties down is-a links as defaults that specific facts can override (penguins cannot fly).
- A taxonomy is an is-a hierarchy, drawn as a tree with a root, parents, children, and leaves (the most specific categories).
- A frame (schema) has slots and fillers, with defaults and inheritance. Production rules are IF-THEN pairs used by expert systems.
- An ontology formally defines a domain's classes, properties, individuals, and rules; unlike a taxonomy, it has many relationship types and lets programs infer new facts.
- A knowledge graph stores facts as subject-predicate-object triples and answers multi-hop questions by following links. Google's Knowledge Graph (2012): "things, not strings."
- The Semantic Web (2001 vision) gives web data machine-readable meaning: RDF models triples, OWL defines ontologies, SPARQL queries them, and Schema.org supplies shared vocabularies.
:::
