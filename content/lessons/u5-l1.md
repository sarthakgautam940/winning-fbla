Machine learning powers spam filters, product recommendations, fraud alerts, and voice assistants, and it is a whole area of the test. This first lesson builds the vocabulary that every later machine learning question assumes: what it means for a program to learn, how learning differs from ordinary programming, and the exact meanings of feature, label, parameter, hyperparameter, model, and inference. Many questions are simply "which of these is the feature?" or "which of these is a hyperparameter?", so precision here pays off all through the unit.

## Programs that improve with experience: task, performance, experience

**Machine learning** (ML) is the field of building systems that learn patterns from data and get better at a task through experience, instead of following rules a person wrote out by hand.

The idea is older than most people expect. In 1959 Arthur Samuel of IBM reported a checkers program that learned to play better than its own programmer, and he is credited with coining, or at least popularizing, the term "machine learning." A popular definition says ML gives computers "the ability to learn without being explicitly programmed"; that phrase is a later paraphrase of Samuel's idea, not a quotation from his paper.

The definition most textbooks use comes from Tom Mitchell's 1997 book *Machine Learning*:

> "A computer program is said to learn from experience E with respect to some class of tasks T and performance measure P, if its performance at tasks in T, as measured by P, improves with experience E."

In plain terms: there is a **task** (T) the program does, a **performance measure** (P) that scores how well it does it, and **experience** (E), usually data, that it learns from. A program learns if more experience raises its score.

::::example[Find T, P, and E]
A spam filter studies emails that users have marked as spam or not spam, and over time it sorts new emails more accurately. Identify T, P, and E.

:::step
The task is what the program does: classifying incoming emails as spam or not spam.
:::

:::step
The performance measure scores the task: the percentage of emails classified correctly.
:::

:::step
The experience is what it learns from: the emails users have already labeled.
:::

:::answer
T = classifying emails, P = the percentage classified correctly, E = the labeled emails.
:::
::::

:::tip
**Test tip.** P is always a number that measures success (accuracy, error, win rate). E is always the data or practice the program learns from. If an option describes what the program does, it is T.
:::

## Machine learning versus traditional programming

In **traditional programming**, a person writes the rules, and the computer applies them to data to produce answers. In **machine learning**, the computer is given data together with the answers, and it works out the rules itself. The learned rules, called a **model**, then turn new data into answers.

| | Traditional programming | Machine learning |
|---|---|---|
| Input | Data and hand-written rules | Data and example answers |
| Output | Answers | A model (learned rules) |
| Example | A tax program that applies a fixed formula | A filter that learns what spam looks like from labeled emails |

ML is a good fit when:

- the rules are too complex to write by hand, as in recognizing faces or understanding speech;
- the patterns change over time, as fraudsters' tactics do;
- many examples are available to learn from;
- an occasional error is acceptable.

ML is a poor fit when a simple, exact rule already solves the problem (converting Celsius to Fahrenheit, computing interest from a legal formula), when there is little data, or when every single decision must be exactly right. A learned model adds error and cost that a fixed rule does not.

## Features, labels, and examples

ML data is organized the same way as the tables of Unit 4:

- An **example** (also called an instance, observation, or sample) is one row: one house, one email, one patient.
- A **feature** is an input variable the model uses to make a prediction, such as a house's size, number of bedrooms, and age. Features are also called attributes or predictors, and in statistics, explanatory or independent variables.
- The **target variable** is the output the model learns to predict, such as the house's sale price. It is also called the **label**, or in statistics, the response or dependent variable.

| size (sq ft) | bedrooms | age (years) | price (target) |
|---|---|---|---|
| 1,800 | 3 | 12 | $310,000 |
| 2,400 | 4 | 5 | $425,000 |
| 1,200 | 2 | 40 | $190,000 |

Each row is an example, the first three columns are features, and price is the target. Data is **labeled** when every example includes the known value of the target; labeled data is what supervised learning needs (lesson 5.2). Choosing and building good features, called feature engineering (lesson 1.7), often matters more than the choice of algorithm.

::check{id="ml-vocab-01"}

## Parameters versus hyperparameters

Two kinds of numbers control a model, and the test loves to mix them up.

**Parameters** are learned from the data during training. The coefficients of a linear regression, the weights and biases of a neural network, and the split points of a decision tree are all parameters. Nobody sets them by hand; training finds them.

A **hyperparameter** is a setting chosen *before* training that controls how the learning happens. Examples:

- the **learning rate** in gradient descent (lesson 5.7);
- the number of neighbors **k** in k-nearest neighbors, and the number of clusters **k** in k-means;
- the maximum depth of a decision tree, and the number of trees in a random forest;
- the strength of regularization (lesson 5.6) and the number of training epochs (lesson 5.9).

Data scientists choose hyperparameters by trying several values and keeping the one that performs best on a **validation set** (lesson 5.5), a process called **hyperparameter tuning**.

:::trap
**Common trap.** In k-means, k is a hyperparameter you choose, but the centroid positions are parameters the algorithm learns. Ask "was this set before training, or found by training?"
:::

::check{id="ml-vocab-02"}

## Models, algorithms, training, and inference [Competitive]

Four more words complete the vocabulary:

- An **algorithm** is the learning procedure, such as the steps that grow a decision tree or the gradient descent that fits a regression.
- A **model** is what the algorithm produces from a particular dataset: the learned function, with its parameters, that makes predictions. Running one algorithm on two different datasets gives two different models.
- **Training** is the learning phase, when the algorithm fits the model's parameters to the training data.
- **Inference** is the application phase, when the trained model makes predictions on new data.

Using a trained model does not change it. A deployed fraud model that scores ten thousand transactions has exactly the same parameters afterward; it learns nothing new unless someone retrains it or it was built to update continuously (online learning, lesson 5.2).

The point of all this is **generalization**: performing well on new data the model has never seen. A model that memorizes its training examples but fails on new ones has learned nothing useful, a problem called overfitting (lesson 5.6).

::check{id="ml-nature-03"}

:::takeaways
- Machine learning builds systems that learn patterns from data and improve with experience instead of following hand-written rules. Arthur Samuel's 1959 checkers program is a classic early example.
- Mitchell's definition: a program learns from experience E on tasks T, measured by P, if its performance at T, measured by P, improves with E.
- Traditional programming: data plus rules give answers. Machine learning: data plus answers give a model. ML fits complex, changing patterns with many examples; it fits poorly when a simple exact rule exists.
- An example is one row; a feature is an input variable; the target variable (label) is what the model predicts. Labeled data includes the target.
- Parameters are learned during training (coefficients, weights, split points). Hyperparameters are set before training (learning rate, k, tree depth, number of trees) and tuned on a validation set.
- An algorithm is the learning procedure; a model is its learned result. Training fits the model; inference uses it, without changing it.
- The goal is generalization to new data, not memorizing the training set.
:::
