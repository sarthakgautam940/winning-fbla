Almost every headline AI system of the past decade, from photo tagging and speech recognition to machine translation and chatbots, is built on deep learning. One test objective asks you to explain the concept, so expect questions on what makes learning "deep," why depth helps, what deep learning needs, and which network design fits which kind of data. This lesson builds directly on the neural networks of lesson 5.9.

## What deep learning is

**Deep learning** is the branch of machine learning that uses neural networks with many layers, called deep neural networks, to learn directly from raw data such as pixels, sound waves, or text. The word "deep" refers to the depth of the network, its number of layers, not to any deep understanding. A network with a single hidden layer is usually called shallow; deep networks have several hidden layers, and modern ones can have dozens or hundreds.

Deep learning sits inside machine learning, which sits inside artificial intelligence:

```figure
type: nested
layers: [Artificial intelligence, Machine learning, Deep learning]
caption: Each field contains the next. All deep learning is machine learning, and all machine learning is AI, but not the other way around.
```

So a decision tree is machine learning but not deep learning, and a chess program that follows hand-written rules is AI but not machine learning.

## Why depth helps: learned features

In classical machine learning, people do much of the thinking about the data. Before training, they design **features**, measurements they expect to matter, a step called **feature engineering**. To classify bird photos, someone might measure beak length and wing color; to filter spam, someone might count links and suspicious words. The model only learns how to combine the features it is given, so it can never be better than those features allow.

Deep learning learns the features itself, which is called **representation learning**. You give a deep network raw pixels, and its layers discover useful features during training. They form a **feature hierarchy**, from simple to complex:

1. The earliest layers respond to simple patterns: edges, color contrasts, small textures.
2. Middle layers combine those into parts: an eye, a wheel, a feather pattern.
3. The last layers combine parts into whole objects: a face, a car, a particular bird.

Each layer reuses what the layer below it found, so depth lets the network build complex concepts out of simple ones. That is why deep learning excels on **unstructured data** such as images, audio, and text (lesson 1.2), where good features are hard for people to write down.

| | Classical machine learning | Deep learning |
|---|---|---|
| Features | Designed by people | Learned from raw data |
| Data needed | Works with small or medium datasets | Needs large datasets |
| Hardware | An ordinary processor is often enough | Usually needs GPUs |
| Best on | Structured tables of features | Images, audio, and text |
| Explaining decisions | Often easier | Hard; often called a black box |

:::trap
**Common trap.** Deep learning is not automatically better. On a small table of numbers, a decision tree, logistic regression, or gradient-boosted trees (lesson 5.8) often match or beat a deep network, train in seconds, and are far easier to explain.
:::

## What deep learning needs: data and compute

Neural networks are decades old (lesson 5.9), so why did deep learning take off only in the 2010s? Three ingredients arrived together.

- **Data.** Deep networks have millions of parameters, and learning them without overfitting takes very large datasets. ImageNet, introduced in 2009, grew to more than 14 million labeled images in about 22,000 categories. Its yearly challenge, held from 2010 to 2017, used about 1.2 million training images in 1,000 categories.
- **Compute.** Training is mostly multiplying large tables of numbers: millions of multiply-and-add operations that do not depend on one another. **Graphics processing units** (GPUs), first built for video games, perform thousands of them at once (lesson 4.7).
- **Better techniques.** ReLU activations (lesson 5.9), dropout (lesson 5.6), and better ways to initialize and connect layers made deep networks trainable.

The turning point came in 2012. **AlexNet**, a deep convolutional network built by Alex Krizhevsky, Ilya Sutskever, and Geoffrey Hinton and trained on two GPUs, won the ImageNet challenge with a top-5 error of 15.3 percent, while the next-best entry had 26.2 percent. (A **top-5 error** counts a prediction as wrong only when the correct label is missing from the model's five best guesses.) The size of that gap drew the whole field toward deep learning.

The same needs are also deep learning's costs: it is expensive to train, uses a great deal of energy, needs large amounts of data, and is hard to explain. **Transfer learning** (lesson 5.2) eases the data problem: start from a network pretrained on a huge dataset, then fine-tune it on your small one.

## Convolutional networks for images

A fully connected layer is a poor fit for images. A 1,000 × 1,000 color photo has 3 million input values (1 million pixels, each with red, green, and blue), so a single dense layer of 1,000 neurons would need 3 billion weights. Worse, it would have to learn what a cat looks like separately for every position in the photo.

A **convolutional neural network** (CNN) solves both problems with **convolutional layers**. A **kernel**, also called a filter, is a small grid of weights, such as 3 × 3. It slides across the image, and at each position it multiplies the pixels it covers by its weights and adds the products. Each result becomes one value in a **feature map**, which shows where in the image the kernel's pattern appears. A layer usually has many kernels, each learning to detect a different pattern.

::::example[One convolution step]
A 3 × 3 kernel with 1s along its diagonal and 0s elsewhere covers this patch of a grayscale image. What value does it produce?

| Row | Image patch | Kernel |
|---|---|---|
| 1 | 2, 0, 1 | 1, 0, 0 |
| 2 | 1, 3, 0 | 0, 1, 0 |
| 3 | 0, 1, 2 | 0, 0, 1 |

:::step
Multiply each pixel by the kernel weight in the same position. Only the three diagonal cells have weight 1, and they hold 2, 3, and 2. Every other product is 0.
:::

:::step
Add the products: 2 + 3 + 2 = 7.
:::

:::answer
The kernel outputs 7 at this position. A patch with a bright diagonal line gives a large value, so this kernel acts as a diagonal-line detector.
:::
::::

Two ideas make convolution powerful. First, the same kernel weights are reused at every position, called **weight sharing**, so a 3 × 3 kernel has only 9 weights (plus a bias) however big the image is, and it detects its pattern wherever the pattern appears. Second, each output depends only on a small neighborhood of pixels, which matches how images work: nearby pixels belong together.

When the kernel moves one pixel at a time (a **stride** of 1) and no border of padding is added, an n × n image and a k × k kernel give a feature map of (n - k + 1) × (n - k + 1). A 6 × 6 image and a 3 × 3 kernel give a 4 × 4 feature map.

A **pooling layer** then shrinks each feature map. **Max pooling** keeps only the largest value in each small window, typically 2 × 2, which halves the width and the height; **average pooling** keeps the mean instead. Pooling cuts computation and makes the network tolerant of small shifts in where a feature appears.

::::example[Max pooling]
Apply 2 × 2 max pooling, with a stride of 2, to this 4 × 4 feature map.

| | Column 1 | Column 2 | Column 3 | Column 4 |
|---|---|---|---|---|
| Row 1 | 1 | 3 | 2 | 0 |
| Row 2 | 4 | 2 | 1 | 5 |
| Row 3 | 0 | 1 | 3 | 2 |
| Row 4 | 2 | 6 | 1 | 1 |

:::step
Split the map into four 2 × 2 windows. The top-left window holds 1, 3, 4, and 2; the top-right window holds 2, 0, 1, and 5.
:::

:::step
The bottom-left window holds 0, 1, 2, and 6; the bottom-right window holds 3, 2, 1, and 1.
:::

:::step
Keep the largest value in each window: 4, 5, 6, and 3.
:::

:::answer
The pooled map is 2 × 2, with 4 and 5 in its top row and 6 and 3 in its bottom row.
:::
::::

A typical CNN repeats convolution (followed by ReLU) and pooling several times, then flattens the result and passes it through fully connected layers to a softmax output.

```figure

steps: [Image, Convolution and ReLU, Pooling, Fully connected layers, Class probabilities]
caption: The usual CNN pipeline. The convolution and pooling stages repeat several times, each finding larger and more complex patterns.
```

CNNs have a long history. In 1989, Yann LeCun and colleagues at AT&T Bell Laboratories trained one with backpropagation to read handwritten ZIP code digits, and after AlexNet's 2012 win, CNNs became the standard tool for image classification, object detection, face recognition, and medical imaging. Very deep CNNs ran into gradients that faded across many layers (lesson 5.9). **ResNet** (2015) solved this with **skip connections**, which add a block's input straight to its output so gradients have a shortcut, and trained networks 152 layers deep.

## Recurrent networks and LSTMs for sequences [Competitive]

Text, speech, music, and stock prices are **sequences**: their order matters, and their lengths vary. A feedforward network takes one fixed-size input and passes it straight through. A **recurrent neural network** (RNN) instead reads a sequence one element at a time and keeps a **hidden state**, a vector that serves as its memory. At each step it combines the new element with the hidden state from the previous step, using the same weights every time. That feedback from one step to the next is a **recurrent connection**, and it is the defining difference from a feedforward network.

Plain RNNs have a short memory. Training them means backpropagating through every time step, and the gradient is multiplied once per step, so over long sequences it vanishes, just as it does across many layers. In the sentence "The keys to the cabinet in the hall are missing," the network must remember that "keys" is plural across six words to predict "are" rather than "is," and a plain RNN often forgets.

The **long short-term memory** (LSTM) network, introduced by Sepp Hochreiter and Jürgen Schmidhuber in 1997, fixes this with a **cell state**, a separate memory line controlled by three **gates**: a forget gate decides what to drop, an input gate decides what to add, and an output gate decides what to pass on. Because the gates learn when to keep information unchanged, both information and gradients can travel across long stretches of a sequence. A simpler gated design, the **gated recurrent unit** (GRU), works on the same idea.

RNNs and LSTMs share one weakness: each step must wait for the step before it, so the positions of a sequence cannot be processed in parallel. That limits how fast they can train on very large datasets.

## Transformers, autoencoders, and GANs [Competitive]

The **transformer**, introduced in 2017 by Ashish Vaswani and seven co-authors, mostly at Google, in the paper "Attention Is All You Need," drops recurrence entirely. It processes every position of a sequence at once and uses **attention** to let each word weigh every other word directly, deciding which ones matter for its meaning. In "The dog chased the ball across the yard until it was tired," attention can link "it" straight back to "dog," however many words lie between them. Because no step waits on another, transformers train efficiently on GPUs and scale to enormous datasets. They power large language models (the T in GPT stands for transformer), and lesson 6.4 shows how attention works.

| | Recurrent network (RNN or LSTM) | Transformer |
|---|---|---|
| Reads a sequence | One step at a time | All positions at once |
| Distant words connect | Through every step in between | Directly, through attention |
| Training | Hard to parallelize | Parallel and fast on GPUs |

An **autoencoder** is a network trained to reproduce its own input. An **encoder** squeezes the input through a narrow middle layer, the **bottleneck**, into a compact code, and a **decoder** rebuilds the input from that code. Because the target is the input itself, no labels are needed, so autoencoders are unsupervised. The bottleneck forces the network to keep only the most important information, which makes autoencoders useful for compression, removing noise, and **anomaly detection**: trained only on normal data, an autoencoder rebuilds unusual inputs badly, so a large reconstruction error flags something worth checking. A variant, the variational autoencoder (VAE), can generate new examples (lesson 6.3).

A **generative adversarial network** (GAN), introduced by Ian Goodfellow and colleagues in 2014, trains two networks against each other. The **generator** turns random noise into fake samples, such as images, and the **discriminator** tries to tell real training samples from the generator's fakes. Each improves by competing: the generator learns to fool the discriminator, and the discriminator learns to catch it, until the fakes look real. That skill also makes GANs one of the tools behind deepfakes (lesson 8.6). Lesson 6.3 compares GANs with the other families of generative models.

Matching an architecture to its data is a frequent question type:

| Architecture | Best fit | Key idea |
|---|---|---|
| Fully connected network | Tables of features | Every neuron connects to every input |
| CNN | Images and other grids | Small kernels slide across the input, sharing weights |
| RNN or LSTM | Sequences: text, speech, time series | A hidden state carries memory from step to step |
| Transformer | Language and other long sequences | Attention connects every position at once |
| Autoencoder | Compression, denoising, anomaly detection | Rebuild the input through a bottleneck |
| GAN | Generating realistic data | A generator and a discriminator compete |

:::tip
**Test tip.** Read the data first. Pixels point to a CNN, ordered sequences to an RNN or LSTM, language at scale to a transformer, "reconstructs its input" to an autoencoder, and "generator and discriminator" to a GAN.
:::

:::takeaways
- Deep learning is machine learning with many-layered neural networks that learn features directly from raw data. "Deep" means many layers. AI contains machine learning, which contains deep learning.
- Depth builds a feature hierarchy: edges, then parts, then whole objects. Classical machine learning relies on hand-engineered features; deep learning learns its own.
- Deep learning needs large datasets and GPUs, costs more, uses more energy, and is harder to explain. On small tables, classical models often win.
- AlexNet (2012), a deep CNN trained on GPUs, won the ImageNet challenge with 15.3 percent top-5 error against 26.2 percent, the field's turning point.
- CNNs slide small kernels over images (multiply and add) and share weights; an n × n image and a k × k kernel give an (n - k + 1) × (n - k + 1) feature map. Max pooling keeps the largest value in each window.
- RNNs carry a hidden state from step to step through recurrent connections but forget over long sequences; LSTMs (1997) add a cell state and gates.
- Transformers (2017) process all positions at once with attention, train in parallel, and power large language models.
- Autoencoders rebuild their input through a bottleneck (unsupervised; good for anomaly detection). GANs pit a generator against a discriminator.
:::
