title: Choosing the right chart
---

A good chart shows in two seconds what a table hides in two hundred numbers. Two official objectives cover charts: selecting the most appropriate visual for a dataset, and describing the different types of diagrams. The typical question describes a dataset and a goal, then asks which chart fits best. This lesson gives you a method that answers those questions in seconds, the features of each common chart, and the tricks that make charts mislead.

## Start from the question

**Visualization** (or data visualization) means representing data graphically so that patterns, trends, and outliers can be seen. Choosing a chart starts with two questions: what do you want the reader to see, and what kinds of variables do you have? Almost every chart question falls into one of five purposes:

| Purpose | The question it answers | Best first choice |
|---|---|---|
| Distribution | How are the values of one numeric variable spread out? | Histogram or boxplot (a dot plot for small data) |
| Comparison | How do categories compare on some number? | Bar chart |
| Change over time | How does a value change over time? | Line chart |
| Relationship | How do two numeric variables move together? | Scatterplot |
| Composition | What share of one whole does each part make up? | Pie chart with few slices, or a stacked bar chart |

A sixth purpose, seeing **many variables at once**, calls for special displays such as heatmaps and scatterplot matrices, covered later in this lesson.

::::example[Pick the chart]
Choose a chart for each goal: (1) monthly app downloads over two years; (2) average rating for each of five phone brands; (3) the spread of 300 delivery times; (4) hours studied against exam score for 80 students.

:::step
Goal 1 tracks one value over time, so use a line chart.
:::

:::step
Goal 2 compares a number across categories, so use a bar chart.
:::

:::step
Goal 3 shows the distribution of one numeric variable, so use a histogram (or a boxplot).
:::

:::step
Goal 4 relates two numeric variables, so use a scatterplot.
:::

:::answer
Line chart, bar chart, histogram, scatterplot.
:::
::::

:::tip
**Test tip.** Underline the goal words in the stem. "Over time" or "trend" points to a line chart; "compare" with categories points to a bar chart; "distribution" or "spread" points to a histogram or boxplot; "relationship" or "correlation" points to a scatterplot; "share" or "percent of the total" points to composition.
:::

## The core charts and what each is for

A **bar chart** shows a number for each category as a bar. The bars are separated by gaps because the categories are separate, and the value axis must start at zero because the bar's length stands for its value. Use horizontal bars when category names are long, and sort the bars by value when the categories have no natural order.

```figure
type: bar
caption: A bar chart compares a number across categories. Each bar starts at zero, so its length is proportional to its value.
xLabel: Region
yLabel: Orders (thousands)
categories: [North, South, East, West]
series:
  - values: [42, 35, 28, 51]
```

A **histogram** shows the distribution of one numeric variable. The number line is cut into equal **bins** (intervals), and each bar's height is the number of values in its bin. The bars touch because the bins cover a continuous range with no gaps. A histogram reveals shape: where values cluster, whether the distribution is skewed, and whether there are gaps or outliers (lesson 3.2).

```figure
type: histogram
caption: A histogram splits one numeric variable into bins. The bars touch because the bins cover a continuous range.
xLabel: Delivery time (minutes)
yLabel: Orders
bins:
  - { from: 0, to: 10, count: 4 }
  - { from: 10, to: 20, count: 11 }
  - { from: 20, to: 30, count: 15 }
  - { from: 30, to: 40, count: 9 }
  - { from: 40, to: 50, count: 5 }
  - { from: 50, to: 60, count: 2 }
```

:::trap
**Common trap.** A histogram and a bar chart look alike but answer different questions. A histogram's horizontal axis is a numeric scale cut into bins; a bar chart's horizontal axis lists categories. If you could reorder the bars without losing meaning, it is a bar chart.
:::

The other core displays:

- A **line chart** connects points in time order, so it shows trends, cycles, and sudden changes. Time goes on the horizontal axis. Do not draw lines between categories that have no order, because the line implies a progression that is not there.
- A **scatterplot** places one dot per observation using two numeric variables, so it shows the direction, form, and strength of a relationship and any outliers (lesson 3.3). The explanatory variable goes on the horizontal axis.
- A **boxplot** draws the five-number summary of a numeric variable, and boxplots side by side are the standard way to compare distributions across groups (lesson 3.2).
- A **bubble chart** is a scatterplot in which each dot's size shows a third numeric variable, such as population.
- A **dot plot** draws each value as a dot above a number line, which suits small datasets.
- A **stem-and-leaf plot** splits each value into a stem (the leading digits) and a leaf (the last digit). Unlike a histogram, it keeps every original value visible. Here, with the key 2 | 3 meaning 23, are the values 12, 15, 17, 20, 23, 23, 28, 31, and 34:

| Stem | Leaves |
|---|---|
| 1 | 2 5 7 |
| 2 | 0 3 3 8 |
| 3 | 1 4 |

When the reader needs exact values rather than a pattern, a plain table can beat any chart.

## Pie charts and when to avoid them

A **pie chart** shows how one whole divides into parts. Each slice's angle is its share of the total, so the slices must add up to 100% of a single whole. A pie works when there are only a few categories, about two to five, with clearly different sizes.

```figure
type: pie
caption: A pie chart works here. There are three slices of one whole, and their sizes are clearly different.
slices:
  - { label: Mobile, value: 58 }
  - { label: Desktop, value: 34 }
  - { label: Tablet, value: 8 }
```

Most readers compare lengths along a common baseline more accurately than they compare angles or areas, so a bar chart usually compares parts more precisely than a pie. Avoid a pie chart when:

- there are many slices, or the slices are close in size;
- the reader must compare shares across several pies;
- the values do not form one whole, as when survey respondents may pick more than one answer and the percentages add up to more than 100%;
- the data change over time, which calls for a line chart.

::check{id="chart-choice-02"}

## Heatmaps, violin plots, and scatterplot matrices [Competitive]

Some displays handle many values or many variables at once.

A **heatmap** is a grid of cells in which color shows the value of each cell. A common use is a correlation matrix: every pair of numeric variables gets a cell, colored by its correlation. Here is a correlation matrix computed from 200 simulated home sales:

| | Price | Size | Age | Distance |
|---|---|---|---|---|
| Price | 1.00 | 0.54 | -0.26 | -0.48 |
| Size | 0.54 | 1.00 | 0.02 | 0.02 |
| Age | -0.26 | 0.02 | 1.00 | -0.13 |
| Distance | -0.48 | 0.02 | -0.13 | 1.00 |

A heatmap would color each cell, with one color for positive values, another for negative values, and a neutral color near 0, so the strong pairs (price and size, price and distance) jump out. That kind of scale, with two colors meeting at a meaningful midpoint, is called **diverging**. For values with no midpoint, such as website visits by day of the week and hour of the day, a **sequential** scale from light to dark fits. Every heatmap needs a color legend.

A **violin plot** is like a boxplot, but its outline is a smoothed histogram mirrored on both sides, so its width shows where values are dense. It reveals shapes a boxplot hides, such as two separate peaks.

A **scatterplot matrix** (also called a pair plot) is a grid of scatterplots, one for every pair of numeric variables, often with each variable's histogram on the diagonal. It is a standard first look during exploratory data analysis. Unlike a correlation heatmap, which reduces each pair to a single number, a scatterplot matrix shows the form of each relationship: curves, clusters, and outliers.

**Small multiples** repeat the same small chart for each group on identical scales, such as one line chart per region, so readers can compare the groups at a glance.

## Charts that mislead [Competitive]

A chart can be accurate in every number and still mislead. Test questions describe these tricks and ask you to name the problem.

- **Truncated axis.** If a bar chart's axis starts at 49 instead of 0, bars for 50 and 52 look wildly different, because the visible parts of the bars are 1 and 3. Bar length must be proportional to value, so a bar chart's axis always starts at zero. A line chart may zoom in when the change itself is the point, but the axis must be clearly labeled.
- **3D effects and area distortion.** Tilting a pie into 3D makes slices near the front look larger. Scaling a picture icon in both height and width to show a doubled value makes it look four times as big, because area grows with the square of the scale.
- **Too many slices.** A pie with a dozen similar slices cannot be read; a sorted bar chart can.
- **Dual axes.** Two lines plotted on two different vertical scales can be made to overlap or cross wherever the designer likes, so any visual alignment between them means little.
- **Cherry-picked ranges.** Starting a time axis right after a crash makes a recovery look like steady growth. Showing only the months that support a claim hides the full trend.

The same six months of satisfaction scores look very different on two vertical scales:

```figure
type: line
caption: Zoomed in, a 1.4-point rise looks dramatic.
xLabel: Month
yLabel: Satisfaction score
yMin: 96
yMax: 97.6
series:
  - points: [[1, 96.1], [2, 96.4], [3, 96.8], [4, 97.0], [5, 97.3], [6, 97.5]]
```

```figure
type: line
caption: On a full 0 to 100 scale, the same rise is barely visible. Neither chart is false, but the first one needs a clearly labeled axis.
xLabel: Month
yLabel: Satisfaction score
yMin: 0
yMax: 100
series:
  - points: [[1, 96.1], [2, 96.4], [3, 96.8], [4, 97.0], [5, 97.3], [6, 97.5]]
```

Good practice follows from these traps: start bar axes at zero, label every axis with units, use a title that states the point, keep scales identical across charts that will be compared, skip 3D and decoration that carries no data, and choose colors that remain distinguishable for colorblind readers.

:::key
**Key idea.** Choose the chart from the question and the variable types. Then make sure the visual size of every mark is proportional to the value it represents.
:::

:::takeaways
- Match the chart to the purpose: distribution (histogram, boxplot), comparison (bar), change over time (line), relationship (scatterplot), composition (pie with few slices, or stacked bar).
- A histogram bins one numeric variable and its bars touch; a bar chart compares categories and its bars have gaps.
- Scatterplots need two numeric variables, with the explanatory variable on the horizontal axis. A bubble chart adds a third variable as dot size.
- Stem-and-leaf and dot plots keep individual values for small datasets.
- Pie charts need parts of one whole and only a few clearly different slices. Use a bar chart otherwise.
- Heatmaps show a grid of values by color, such as a correlation matrix; violin plots show distribution shape; scatterplot matrices show every pairwise relationship.
- Misleading charts: truncated bar axes, 3D and area distortion, too many slices, dual axes, and cherry-picked ranges.
:::
