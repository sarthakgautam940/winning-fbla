title: Search and the kinds of reasoning problems

Many AI problems are really search problems: finding a route, solving a puzzle, scheduling tasks, or choosing a chess move all mean exploring a space of possibilities for a good one. This lesson shows how to set up a problem for search, how the basic strategies explore, how heuristics and game search make them practical, and finally how to match any reasoning problem to the right kind of algorithm. Expect questions that trace a search order, compute a small game value, or classify a problem.

## Problems as state spaces: states, operators, start, goal

To solve a problem by search, describe it with four parts:

- A **state** is one configuration of the world: a location on a map, or an arrangement of puzzle tiles.
- **Operators**, also called actions, change one state into another: drive along a road, slide a tile.
- The **start state** is where the search begins.
- The **goal state**, or a goal test, says when the problem is solved.

Many problems also have a **path cost**, such as distance or time, so some solutions are better than others. All the states reachable from the start form the **state space**, and searching builds a **search tree** of the paths explored so far.

| Problem | States | Operators | Start | Goal |
|---|---|---|---|---|
| Route planning | Locations | Travel along a road | Home | School |
| Sliding-tile puzzle | Arrangements of the tiles | Slide a tile into the empty space | The scrambled board | Tiles in order |
| Packing a truck | Which boxes are where | Place a box in a spot | An empty truck | All boxes fit |

AI4K12 lists task planning, scheduling, resource allocation, and packing objects into containers as typical real-world search problems.

## Breadth-first and depth-first search

The two basic strategies differ only in which node they explore next.

- **Breadth-first search** (BFS) explores level by level: the start, then everything one step away, then everything two steps away, and so on. It keeps the nodes waiting to be explored in a queue (first in, first out).
- **Depth-first search** (DFS) follows one branch as deep as it goes before backing up to try the next. It keeps its waiting nodes in a stack (last in, first out).

```figure
type: tree
caption: A small search tree. Breadth-first search visits A, B, C, D, E, F, G (level by level). Depth-first search, taking children left to right, visits A, B, D, E, C, F, G (down each branch first).
root:
  label: A (start)
  children:
    - label: B
      children:
        - { label: D }
        - { label: E }
    - label: C
      children:
        - { label: F }
        - { label: G }
```

The orders explain the trade-offs. If the goal is C, BFS finds it third, while DFS first wanders through B, D, and E. If the goal is D, DFS gets there third, ahead of BFS.

| | Breadth-first search | Depth-first search |
|---|---|---|
| Finds | The shallowest goal (fewest steps) first | Whatever goal its branch reaches first |
| Memory | A lot: it stores every node at the current level, and levels grow exponentially | Little: just the current path and the siblings along it |
| Risk | Running out of memory on large problems | Wandering down a very deep or endless branch |

Neither strategy looks at path cost, so neither is guaranteed to find the cheapest solution when steps have different costs. When every step costs the same, BFS does find a shortest path.

## Best-first search, heuristics, and A* [Competitive]

When the state space is too large to search blindly, AI uses a **heuristic**: a rule of thumb that estimates how far a state is from the goal. For route finding, a common heuristic is the straight-line distance to the destination, which is easy to compute and roughly tracks the true road distance.

- **Greedy best-first search** always expands the node that the heuristic says is closest to the goal. It is fast, but it ignores the cost already paid, so it can be lured down a path that looks promising but turns out long.
- **A\* search** (A-star) expands the node with the lowest

$$
f(n) = g(n) + h(n)
$$

where g(n) is the cost of the path so far and h(n) is the heuristic's estimate of the remaining cost. If the heuristic never overestimates the true remaining cost, it is called **admissible**, and A\* is guaranteed to find a least-cost path. A\* is a standard method for route planning and for moving characters around in video games.

::::example[A* versus greedy best-first]
Two nodes wait to be expanded. Node X has a path cost so far of 6 and a heuristic estimate of 3. Node Y has a path cost so far of 2 and an estimate of 5. Which node does each search expand next?

:::step
Greedy best-first looks only at the estimate h: X has 3 and Y has 5, so it expands X.
:::

:::step
A* adds the cost so far: X has f = 6 + 3 = 9, and Y has f = 2 + 5 = 7.
:::

:::answer
Greedy best-first expands X, but A* expands Y, the node whose total estimated path is cheaper. Counting the cost already paid is what lets A* find least-cost paths.
:::
::::

## Adversarial search: minimax and alpha-beta pruning [Champion]

In games such as chess, checkers, or tic-tac-toe, an opponent works against you. **Adversarial search** handles this with a game tree whose levels alternate between two players: MAX, who wants the highest score, and MIN, who wants the lowest.

The **minimax** algorithm assigns values from the bottom up. Each leaf has a score. A MIN node takes the smallest value among its children, since MIN will choose the move worst for MAX, and a MAX node takes the largest. The root's value is the best outcome MAX can guarantee against an opponent who plays perfectly.

```figure
type: tree
caption: A two-level game tree. MIN would choose 3 on the left and 2 on the right, so MAX moves left and is guaranteed a value of 3.
root:
  label: "MAX: 3"
  children:
    - label: "MIN: 3"
      children:
        - { label: "3" }
        - { label: "5" }
    - label: "MIN: 2"
      children:
        - { label: "2" }
        - { label: "9" }
```

**Alpha-beta pruning** reaches the same answer as minimax while examining fewer nodes, by skipping branches that cannot change the decision. In the tree above, once the left MIN node is known to be worth 3, the search looks at the right MIN node's first leaf, 2. MIN can now hold the right branch to 2 or less, which is worse for MAX than the 3 already available, so the leaf 9 never needs to be examined. Pruning lets a program search deeper in the same time.

Real games are far too large to search to the end, so programs search a limited number of moves ahead and score the positions there with an **evaluation function**. IBM's Deep Blue, which beat world champion Garry Kasparov in 1997, could evaluate 200 million chess positions per second.

## The kinds of reasoning problems and an algorithm for each

AI4K12 sorts reasoning problems into eight types and pairs each with algorithms that solve it. Learning the pairs lets you match any scenario to an approach:

| Problem type | The question it answers | Example | Typical algorithms |
|---|---|---|---|
| Classification | Which category does this belong to? | Is this transaction fraud? | Decision trees, nearest neighbors, neural networks |
| Prediction | What number should we expect? | Tomorrow's electricity demand | Regression, neural networks |
| Sequential decision | Which series of actions earns the most reward? | A robot learning to walk | Reinforcement learning (Q-tables or neural networks) |
| Combinatorial search | Which arrangement or path works? | Packing boxes, solving a puzzle | Breadth-first and depth-first search |
| Heuristic search | What is a good path when the space is huge? | Route planning across a country | Best-first search, A* |
| Adversarial search | What is the best move against an opponent? | Chess, checkers | Minimax with alpha-beta pruning |
| Logical deduction | What follows for certain from facts and rules? | Checking graduation requirements | Resolution theorem proving, IF-THEN rules |
| Statistical inference | What is probably true given uncertain evidence? | Diagnosing a disease from symptoms | Bayesian networks |

Some of these algorithms work on **symbolic** representations, such as search trees and logical rules, and others on **numerical** ones, such as neural networks operating on feature vectors. The choice follows the data. A decision tree cannot work directly on the raw pixels of an image, but a neural network can, because it extracts its own features (lesson 5.10). A Sudoku, on the other hand, has exact rules and a clear goal, so symbolic search is the natural tool.

:::tip
**Test tip.** Look for the verbs. "Categorize" points to classification, "estimate a number" to prediction, "learn by trial and error over many steps" to sequential decisions, "beat an opponent" to adversarial search, "derive for certain" to deduction, and "most likely given evidence" to statistical inference.
:::

:::takeaways
- A search problem has states, operators (actions), a start state, a goal state or test, and often a path cost. The reachable states form the state space.
- Breadth-first search goes level by level (a queue), finds the shallowest goal, and uses a lot of memory. Depth-first search goes down one branch at a time (a stack) and uses little memory. Neither considers path cost.
- A heuristic estimates the distance to the goal. Greedy best-first expands the lowest h(n); A* expands the lowest f(n) = g(n) + h(n), and with an admissible heuristic (one that never overestimates) it finds a least-cost path.
- Minimax: MIN nodes take the minimum of their children, MAX nodes the maximum, and the root value is MAX's guaranteed outcome. Alpha-beta pruning skips branches that cannot change the decision, giving the same answer with fewer nodes.
- AI4K12's reasoning problems and algorithms: classification (decision trees, neural networks), prediction (regression), sequential decision (reinforcement learning), combinatorial search (BFS, DFS), heuristic search (A*), adversarial search (alpha-beta), logical deduction (resolution, IF-THEN rules), and statistical inference (Bayesian networks).
- Symbolic methods suit exact rules and clear goals; numerical methods such as neural networks suit raw, messy data like images.
:::
