title: Measuring model performance
---

Building a model is half the job; the other half is measuring how good it is. A model that looks impressive by one measure can be useless by another, and test writers love that gap. Expect to compute metrics from a confusion matrix or a few predictions, to choose the right metric for a situation, to recognize when accuracy misleads, and to read an ROC curve. Every formula in this lesson is short, and you should be able to apply each one in under 30 seconds.

## Errors for numeric predictions: MAE, MSE, RMSE, R squared

For a model that predicts numbers, each prediction's **error** is its residual: actual minus predicted. Three standard metrics summarize the errors:

- **Mean absolute error (MAE)**: the average of the absolute errors. It is in the same units as y and easy to explain: "on average, predictions miss by $12,000."
- **Mean squared error (MSE)**: the average of the squared errors. Its units are squared (dollars squared), and squaring makes large errors count heavily: an error of 10 contributes 100.
- **Root mean squared error (RMSE)**: the square root of the MSE. It returns to the units of y but keeps the extra weight on large errors.

::::example[MAE, MSE, and RMSE]
A model predicts 11, 12, 13, and 24 for four cases whose actual values are 10, 12, 15, and 20. Find the MAE, MSE, and RMSE.

:::step
Errors (actual minus predicted): 10 - 11 = -1, 12 - 12 = 0, 15 - 13 = 2, and 20 - 24 = -4.
:::

:::step
MAE: the absolute errors are 1, 0, 2, and 4, so MAE = 7 / 4 = 1.75.
:::

:::step
MSE: the squared errors are 1, 0, 4, and 16, so MSE = 21 / 4 = 5.25.
:::

:::step
RMSE: $$\sqrt{5.25} \approx 2.29$$.
:::

:::answer
MAE = 1.75, MSE = 5.25, and RMSE is about 2.29. The single error of 4 pulls the RMSE well above the MAE.
:::
::::

RMSE is always at least as large as MAE, and the gap grows when a few errors are much larger than the rest. Choose MAE when every unit of error costs the same; choose RMSE (or MSE) when large misses are especially costly. **R squared** (lesson 3.6) completes the set: it has no units and gives the share of the variation in y that the model explains.

## The confusion matrix

For a model that predicts classes, compare each prediction with the truth. With two classes, call the one you are looking for (spam, disease, fraud) the **positive** class and the other the **negative** class. Every prediction then lands in one of four cells of the **confusion matrix**:

- **True positive (TP)**: predicted positive, actually positive.
- **False positive (FP)**: predicted positive, actually negative. A false alarm, which is a Type I error (lesson 2.6).
- **False negative (FN)**: predicted negative, actually positive. A miss, which is a Type II error.
- **True negative (TN)**: predicted negative, actually negative.

```figure
type: confusion
caption: A spam filter tested on 200 emails. It caught 40 spam emails, missed 20, raised 10 false alarms, and correctly passed 130 legitimate emails.
tp: 40
fp: 10
fn: 20
tn: 130
positive: Spam
negative: Not spam
```

:::trap
**Common trap.** Different books and software lay out the matrix differently: some put the actual classes in the rows and others put them in the columns. Read the labels before you read the numbers.
:::

## Accuracy, precision, recall, specificity, F1

Each metric answers a different question. Using the spam filter's matrix (TP = 40, FP = 10, FN = 20, TN = 130, total 200):

| Metric | Formula | Question it answers | Spam filter |
|---|---|---|---|
| **Accuracy** | (TP + TN) / total | What share of all predictions were right? | 170 / 200 = 0.85 |
| **Precision** | TP / (TP + FP) | Of the cases flagged positive, how many really were? | 40 / 50 = 0.80 |
| **Recall** | TP / (TP + FN) | Of the real positives, how many were caught? | 40 / 60 = 0.67 |
| **Specificity** | TN / (TN + FP) | Of the real negatives, how many were cleared? | 130 / 140 = 0.93 |

Recall is also called **sensitivity** or the **true positive rate**. The **false positive rate** is FP / (FP + TN) = 10 / 140, about 0.07, which equals 1 minus the specificity.

The **F1 score** combines precision and recall into one number, their **harmonic mean**:

$$
F_1 = \frac{2 \times \text{precision} \times \text{recall}}{\text{precision} + \text{recall}}
$$

::::example[F1 for the spam filter]
Find the F1 score for the spam filter, using precision 0.80 and recall 40 / 60.

:::step
Recall is 40 / 60, about 0.667. Multiply: 2 × 0.80 × 0.667 = 1.067.
:::

:::step
Add: 0.80 + 0.667 = 1.467.
:::

:::step
Divide: 1.067 / 1.467, about 0.727.
:::

:::answer
F1 is about 0.727, just under the simple average of 0.80 and 0.667 (0.733), because a harmonic mean leans toward the smaller of the two values.
:::
::::

That last property is the reason for using a harmonic mean: a model with precision 0.9 and recall 0.1 has an F1 of only 0.18, while a plain average would flatter it with 0.5.

:::tip
**Test tip.** Keep precision and recall straight by their denominators. Precision divides by everything the model **predicted** positive. Recall divides by everything that **actually** was positive.
:::

## When accuracy lies: imbalanced classes [Competitive]

When one class is rare, accuracy can be badly misleading. Suppose 1 transaction in 100 is fraud. A "model" that labels every transaction as legitimate is right 99% of the time, yet it catches no fraud at all: its recall is 0. This is the **accuracy paradox**. For **imbalanced classes**, judge a model by its confusion matrix and by precision, recall, F1, or balanced accuracy (the average of recall and specificity).

Common fixes for imbalance:

- **Resample** the training data: oversample the rare class (or create synthetic examples of it, as the SMOTE technique does) or undersample the common class.
- **Weight the classes** so mistakes on the rare class cost more during training.
- **Move the threshold** (see the Champion section below).
- **Collect more examples** of the rare class when possible.

::check{id="metric-choice-01"}

## Precision or recall? Matching the metric to the cost

The right metric depends on which mistake hurts more.

| Situation | Worse mistake | Prioritize |
|---|---|---|
| Screening for a serious disease | Missing a sick patient (FN) | Recall |
| Detecting credit card fraud | Missing fraud (FN) | Recall |
| Filtering spam | Sending a real email to junk (FP) | Precision |
| Flagging people for investigation | Accusing an innocent person (FP) | Precision |
| Both mistakes matter about equally | Either | F1 |

In screening, a false alarm leads to a follow-up test, but a miss can be deadly, so recall comes first. In spam filtering, a missed spam email is a small annoyance, but a lost job offer is a disaster, so precision comes first.

## Thresholds, ROC curves, and AUC [Champion]

Most classifiers output a score or probability, and a **threshold** turns it into a class (lesson 3.6). Moving the threshold trades precision against recall. **Lowering** it labels more cases positive, which catches more real positives (recall rises) but admits more false alarms (precision usually falls). **Raising** it does the reverse.

Try it: the widget scores 20 emails, 8 of them spam. At the default threshold of 0.5, the model catches 6 of the 8 spam emails (recall 0.75), and 6 of its 9 spam flags are correct (precision about 0.67). Raise the threshold to 0.7 and it flags only 5 emails, 4 of them spam: precision rises to 0.80 while recall falls to 0.50.

::widget{name="threshold-explorer"}

An **ROC curve** (receiver operating characteristic) shows the whole trade-off at once. It plots the true positive rate (recall) against the false positive rate for every possible threshold. A perfect model reaches the top-left corner (catching every positive with no false alarms), and a model that guesses at random follows the diagonal.

```figure
type: line
caption: An ROC curve. The model's curve bows toward the top-left corner, well above the diagonal of random guessing. The area under it is about 0.87.
xLabel: False positive rate
yLabel: True positive rate (recall)
yMin: 0
yMax: 1
series:
  - name: Model
    points: [[0, 0], [0.05, 0.45], [0.1, 0.65], [0.2, 0.8], [0.35, 0.9], [0.6, 0.97], [1, 1]]
  - name: Random guessing
    points: [[0, 0], [1, 1]]
```

The **AUC** (area under the ROC curve) summarizes the curve in one number. An AUC of 1.0 is a perfect model and 0.5 is no better than random guessing. AUC has a neat interpretation: it is the probability that the model gives a randomly chosen positive case a higher score than a randomly chosen negative case. Because it covers every threshold, AUC compares models before anyone chooses a threshold.

:::takeaways
- MAE averages absolute errors and is in y's units; MSE averages squared errors (squared units); RMSE is the square root of MSE. RMSE is at least MAE and punishes large errors more.
- Confusion matrix: TP, FP (false alarm, Type I), FN (miss, Type II), TN. Read the labels; layouts vary.
- Accuracy = (TP + TN) / total. Precision = TP / (TP + FP). Recall = TP / (TP + FN). Specificity = TN / (TN + FP). False positive rate = 1 - specificity.
- F1 = 2PR / (P + R), the harmonic mean, which stays low if either precision or recall is low.
- With imbalanced classes, accuracy misleads (the accuracy paradox). Use recall, precision, F1, or balanced accuracy, and fix imbalance by resampling, class weights, or threshold changes.
- Prioritize recall when misses are costly (disease screening, fraud) and precision when false alarms are costly (spam filters, accusations).
- Lowering the threshold raises recall and usually lowers precision. An ROC curve plots recall against the false positive rate; AUC runs from 0.5 (random) to 1.0 (perfect).
:::
