The first objective in the tools area is "Write queries in SQL," and SQL questions are some of the most reliable points on the test once you can read a query at a glance. They come in three shapes: pick the query that does a job, predict what a query returns, or count the rows it returns. This lesson covers retrieving, sorting, and filtering rows, including the NULL rules that trip up even experienced analysts. Every example runs against the course's **school** database (Reference page), and every result shown is the real output.

## SELECT and FROM

**SQL** (Structured Query Language) is the standard language for working with relational databases; its formal standard is ISO/IEC 9075. A **query** is a request for data written in SQL. The simplest query names the columns you want and the table they come from:

```sql run db=school
SELECT club_name, advisor FROM clubs;
```

| club_name | advisor |
|---|---|
| Robotics | Ms. Park |
| Debate | Mr. Reyes |
| Data Science | Dr. Osei |
| Chess | Ms. Lin |

A few ground rules:

- `SELECT` lists the columns to return, and `FROM` names the table. `SELECT *` returns every column.
- SQL keywords are not case-sensitive, but writing them in capitals is the convention, and a semicolon ends a statement.
- Text values go in single quotes, such as `'Ava'`; numbers do not.
- A query reads data without changing it. Without an ORDER BY clause, the database may return rows in any order.

::check{id="sql-select-01"}

## Aliases, DISTINCT, ORDER BY, LIMIT

An **alias**, written with `AS`, renames a column (or a table) in the result:

```sql run db=school
SELECT name AS student, gpa FROM students WHERE grade = 9;
```

| student | gpa |
|---|---|
| Grace | 3.4 |

`DISTINCT` removes duplicate rows from the result. Ten students span only four grades:

```sql run db=school
SELECT DISTINCT grade FROM students ORDER BY grade;
```

| grade |
|---|
| 9 |
| 10 |
| 11 |
| 12 |

With several columns, DISTINCT removes rows whose whole combination of values repeats.

`ORDER BY` sorts the result, ascending (`ASC`) by default or descending with `DESC`. With two sort columns, the second breaks ties in the first. `LIMIT n` then keeps only the first n rows:

```sql run db=school
SELECT name, grade FROM students ORDER BY grade DESC, name LIMIT 4;
```

| name | grade |
|---|---|
| Chloe | 12 |
| Farid | 12 |
| Jonah | 12 |
| Ben | 11 |

The three seniors come first, in alphabetical order, and then the first junior alphabetically.

A **top-N query** combines the two: sort by the value you care about, descending, then limit. Chloe and Hiro tie at 3.9, so a second sort column (`name`) makes the order predictable:

```sql run db=school
SELECT name, gpa FROM students ORDER BY gpa DESC, name LIMIT 3;
```

| name | gpa |
|---|---|
| Chloe | 3.9 |
| Hiro | 3.9 |
| Elena | 3.8 |

LIMIT is the keyword in PostgreSQL, MySQL, and SQLite. SQL Server writes `SELECT TOP 3`, and the SQL standard spells it `FETCH FIRST 3 ROWS ONLY`. All of them mean the same thing.

:::trap
**Common trap.** LIMIT without ORDER BY returns some rows, but which ones is not guaranteed. "The top 3" only means something after the rows are sorted.
:::

::check{id="sql-select-02"}

## WHERE with comparisons

`WHERE` filters rows, keeping only those for which its condition is true. It uses the comparison operators `=`, `<>` (not equal; many systems also accept `!=`), `<`, `>`, `<=`, and `>=`:

```sql run db=school
SELECT name, grade FROM students WHERE grade = 11 ORDER BY name;
```

| name | grade |
|---|---|
| Ben | 11 |
| Elena | 11 |
| Hiro | 11 |

The clauses always appear in this written order: SELECT, FROM, WHERE, ORDER BY, LIMIT. (Lesson 4.3 adds GROUP BY and HAVING, and explains the different order in which the database actually processes them.)

::check{id="sql-where-01"}

## AND, OR, NOT, and parentheses

Conditions combine with `AND` (both must be true), `OR` (at least one must be true), and `NOT` (reverses a condition). When they are mixed, SQL applies **NOT first, then AND, then OR**, just as multiplication comes before addition in arithmetic.

That order changes results. Suppose you want students in grade 10 or 12 who have a GPA above 3.5:

```sql run db=school
SELECT name FROM students WHERE grade = 10 OR grade = 12 AND gpa > 3.5 ORDER BY name;
```

| name |
|---|
| Ava |
| Chloe |
| Dev |
| Isla |

Because AND binds first, SQL read this as "grade 10, or (grade 12 and GPA above 3.5)," so every tenth grader slipped in regardless of GPA. Parentheses fix it:

```sql run db=school
SELECT name FROM students WHERE (grade = 10 OR grade = 12) AND gpa > 3.5 ORDER BY name;
```

| name |
|---|
| Ava |
| Chloe |

:::tip
**Test tip.** Whenever a WHERE clause mixes AND with OR and has no parentheses, mentally put parentheses around each AND pair first. That is how the database reads it.
:::

::check{id="sql-where-02"}

## IN, BETWEEN, LIKE

Three shortcuts make filters shorter and clearer.

`IN` tests membership in a list. `WHERE grade IN (9, 12)` means the same as `WHERE grade = 9 OR grade = 12`:

```sql run db=school
SELECT name FROM students WHERE grade IN (9, 12) ORDER BY name;
```

| name |
|---|
| Chloe |
| Farid |
| Grace |
| Jonah |

`BETWEEN low AND high` tests a range and is **inclusive**: both endpoints count. Ava's GPA of exactly 3.6 is included here:

```sql run db=school
SELECT name, gpa FROM students WHERE gpa BETWEEN 3.0 AND 3.6 ORDER BY name;
```

| name | gpa |
|---|---|
| Ava | 3.6 |
| Dev | 3.2 |
| Grace | 3.4 |
| Jonah | 3.1 |

`LIKE` matches text patterns with two wildcards: **`%` matches any run of characters (including none)**, and **`_` matches exactly one character**. So `'A%'` means "starts with A," `'%a'` means "ends with a," and `'_e%'` means "the second letter is e":

```sql run db=school
SELECT name FROM students WHERE name LIKE '_e%' ORDER BY name;
```

| name |
|---|
| Ben |
| Dev |

Each of these can be negated: `NOT IN`, `NOT BETWEEN`, `NOT LIKE`. Whether LIKE cares about capital letters depends on the system: PostgreSQL's LIKE is case-sensitive (it offers ILIKE for case-insensitive matching), while SQLite's ignores the case of ordinary letters by default.

::check{id="sql-where-03"}

## NULL and IS NULL [Competitive]

**NULL** means a value is missing or unknown. It is not zero and not an empty string. Ben and Farid have NULL in `club_id` (no club), and Isla has a NULL `gpa`.

Any comparison with NULL is neither true nor false but **unknown**, and WHERE keeps only rows where the condition is true. So `WHERE gpa = NULL` matches nothing, not even Isla. To test for missing values, use **`IS NULL`** or **`IS NOT NULL`**:

```sql run db=school
SELECT name FROM students WHERE club_id IS NULL ORDER BY name;
```

| name |
|---|
| Ben |
| Farid |

The unknown result surprises people in a second way. This condition looks as if it covers every student, yet it returns 9 rows, not 10:

```sql run db=school
SELECT COUNT(*) AS students_counted FROM students WHERE gpa > 3.5 OR gpa <= 3.5;
```

| students_counted |
|---|
| 9 |

For Isla, both comparisons are unknown, so Isla's row is filtered out.

NULL spreads through arithmetic too: `gpa * 10` is NULL for Isla. The function **`COALESCE`** returns its first non-NULL argument, so `COALESCE(gpa, 0)` turns a missing GPA into 0 for display or calculation.

Finally, aggregate functions skip NULLs. `COUNT(*)` counts rows (10 students), while `COUNT(gpa)` counts non-NULL values (9), and `AVG(gpa)` averages only the 9 known GPAs. Lesson 4.3 builds on this. Where NULLs land when you sort also varies by system: PostgreSQL puts them last in ascending order, SQLite puts them first.

:::trap
**Common trap.** `= NULL` is never true, so a query that uses it silently returns nothing. Always write `IS NULL`.
:::

::check{id="sql-null-01"}

:::takeaways
- SQL (Structured Query Language) is the standard language for relational databases; a query is a request for data.
- Written clause order: SELECT, FROM, WHERE, ORDER BY, LIMIT. SELECT * returns every column; AS creates an alias.
- DISTINCT removes duplicate rows. ORDER BY sorts ascending by default (DESC for descending), with later columns breaking ties. LIMIT n keeps the first n rows, so sort first for a top-N query.
- WHERE keeps rows whose condition is true. Comparison operators: =, <> (not equal), <, >, <=, >=. Text goes in single quotes.
- NOT binds first, then AND, then OR. Use parentheses when mixing AND and OR.
- IN tests a list; BETWEEN is inclusive of both ends; in LIKE, % matches any run of characters and _ matches exactly one.
- NULL means unknown. Comparisons with NULL are unknown, so use IS NULL, never = NULL. Arithmetic with NULL gives NULL; COALESCE supplies a default.
- COUNT(*) counts rows; COUNT(column) and AVG(column) skip NULLs.
:::
