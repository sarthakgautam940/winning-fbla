This lesson fills in the everyday tools around the libraries: Python's built-in data types, how to read short Python code, the notebooks and environments data scientists work in, version control with Git and GitHub, and the other languages in the field. Test questions here are quick: pick the right data type, predict what a few lines print, name the error, or match a tool to its job. Each is a fast point once the vocabulary is familiar.

## Python's core data types: list, tuple, dictionary, set

Besides single values, such as integers (`7`), floats (`3.6`), strings (`"data"`), booleans (`True`, `False`), and `None`, Python has four built-in collections:

| Type | Example | Ordered? | Changeable? | Duplicates? | Typical use |
|---|---|---|---|---|---|
| **list** | `[4, 7, 1, 9]` | Yes | Yes | Allowed | A sequence that grows or changes |
| **tuple** | `(3, 4)` | Yes | No | Allowed | A fixed record, such as a coordinate pair |
| **dictionary** | `{"Ava": 3.6}` | Yes (insertion order) | Yes | Keys must be unique | Looking up a value by its key |
| **set** | `{101, 205}` | No | Yes | No | Unique items and fast membership tests |

A dictionary maps **keys** to **values**: `gpa["Ava"]` looks up Ava's GPA directly instead of searching a list. A set keeps only unique items, so converting a list to a set removes its duplicates:

```python run
visits = [101, 205, 101, 330, 205]
unique = set(visits)
print(sorted(unique), len(unique))

gpa = {"Ava": 3.6, "Ben": 2.9}
print(gpa["Ava"], gpa.get("Zoe", 0))
```

```output
[101, 205, 330] 3
3.6 0
```

The method `get(key, default)` returns the default instead of an error when a key is missing; Zoe is not in the dictionary, so it returns 0.

## Mutability, indexing, and slicing [Competitive]

A **mutable** object can be changed after it is created; an **immutable** one cannot. Lists, dictionaries, and sets are mutable. Tuples and strings are immutable, so trying to change one raises an error:

```python
point = (3, 4)
point[0] = 5   # TypeError: 'tuple' object does not support item assignment
```

Python **indexes from 0**: the first element of a list is `nums[0]`. Negative indexes count from the end, so `nums[-1]` is the last element. A **slice** `nums[start:stop]` takes the elements from `start` up to **but not including** `stop`, and `[::-1]` reverses a sequence. Strings index and slice the same way.

```python run
nums = [4, 7, 1, 9]
print(nums[0], nums[-1], nums[1:3])

word = "data"
print(word[1:], word[::-1])

a = [1, 2]
b = a
b.append(3)
print(a)
```

```output
4 9 [7, 1]
ata atad
[1, 2, 3]
```

The last example is a classic trap. `b = a` does not copy the list; it gives the same list a second name, so appending through `b` also changes `a`. To make an independent copy, write `b = a.copy()` or `b = list(a)`.

:::trap
**Common trap.** Python and R count differently. Python's `nums[1:3]` is the second and third elements and stops before position 3, while R's `x[2:3]` uses positions 2 and 3 because R counts from 1 and includes both ends. And Python's `nums[-1]` is the last element, while R's `x[-1]` removes the first.
:::

## Reading short Python: loops, conditions, comprehensions [Competitive]

Most code questions use only a few constructs:

- A **for loop** repeats a block for each item: `for x in [2, 4, 6]:`. `range(start, stop)` produces whole numbers from start up to but not including stop, so `range(1, 10)` gives 1 through 9.
- **if**, **elif**, and **else** choose between blocks. The `%` operator gives a remainder, so `i % 3 == 0` tests whether i is divisible by 3.
- `total += x` adds x to total; it is short for `total = total + x`.
- A **list comprehension** builds a list in one line: `[expression for x in items if condition]`.

```python run
total = 0
for x in [2, 4, 6]:
    total += x
print(total)

print([x * 10 for x in range(3)])
print([n for n in [3, 15, 9, 21] if n > 10])
```

```output
12
[0, 10, 20]
[15, 21]
```

When code fails, the error's name tells you what went wrong:

| Error | Meaning | Example |
|---|---|---|
| **KeyError** | A dictionary has no such key | `gpa["Zoe"]` |
| **IndexError** | A position is past the end of a sequence | `[1, 2, 3][3]` |
| **TypeError** | An operation does not fit the types involved | `"3" + 4`, or changing a tuple |
| **ValueError** | The type is right but the value is not | `int("abc")` |
| **NameError** | A name has not been defined | using `totl` for `total` |

:::tip
**Test tip.** To predict a loop's output, write a tiny table on your scratch paper with one column per variable and one row per pass through the loop. Most errors come from forgetting that `range` and slices stop before their end value.
:::

## Notebooks and environments: Jupyter, JupyterLab, Anaconda, pip

A **Jupyter notebook** (a file ending in `.ipynb`) is a document made of **cells**. **Code cells** hold code, and their output (numbers, tables, charts) appears right below them; **Markdown cells** hold formatted text that explains the analysis. Behind the notebook runs the **kernel**, the process that executes the code and remembers every variable created so far. JupyterLab is a fuller editing environment for notebooks, and Google Colab runs notebooks in a web browser on remote servers.

Because the kernel remembers whatever has run, cells can be run in any order, and a notebook can work for its author while failing for someone who runs it from top to bottom. Restarting the kernel and running every cell in order is the simple test of whether a notebook is reproducible.

Projects also depend on specific packages and versions:

- **pip** installs Python packages from the Python Package Index (PyPI): `pip install pandas`.
- **conda** is a package and environment manager that can install Python itself along with packages.
- **Anaconda** is a distribution that bundles Python, conda, and hundreds of data science packages in one installation.

A **virtual environment** keeps each project's packages separate, so one project can use an older version of a library without breaking another. Recording the packages in a file, such as `requirements.txt` for pip or `environment.yml` for conda, lets anyone rebuild the same setup, which supports reproducibility (lesson 1.8).

## Git and GitHub: repository, commit, branch, merge, pull request

**Git** is a version-control system: it records snapshots of a project's files over time, so you can see every change, return to any earlier version, and work on several ideas at once. **GitHub** is a website that hosts Git repositories online and adds tools for teams, such as pull requests and issue tracking; GitLab and Bitbucket offer similar services. Git runs on your own computer, even offline; GitHub is a place to share and collaborate on Git repositories.

The core vocabulary:

- A **repository** (repo) is a project folder whose history Git tracks.
- **Clone** copies a remote repository, with its full history, onto your computer.
- A **commit** is a saved snapshot of changes, with a message describing them.
- A **branch** is an independent line of development, such as a branch for trying a new model while the main branch stays stable.
- **Merge** combines one branch's commits into another. If both branches changed the same lines, Git reports a **merge conflict** for a person to resolve.
- **Push** sends your commits to the remote repository, and **pull** brings others' commits down to yours.
- A **pull request**, on GitHub, proposes merging a branch and lets teammates review and discuss the changes before they are merged.

A typical team workflow: clone the repository, create a branch, make and commit changes, push the branch, open a pull request, review, and merge.

## The languages of data science and where each fits

| Language | Where it fits best |
|---|---|
| Python | General-purpose data science, machine learning, deep learning, automation |
| R | Statistics, statistical modeling, and visualization |
| SQL | Querying and managing relational databases |
| Scala | Big data processing; it is the language Apache Spark is written in |
| Java | Large enterprise systems and many big data platforms |
| Julia | High-performance numerical and scientific computing |
| JavaScript | Interactive charts and dashboards in web browsers |

Tools are also either open source or commercial. **Open-source** tools, such as Python, R, Julia, Jupyter, and PostgreSQL, are free to use and inspect, and are improved by their communities. **Commercial** tools, such as SAS, MATLAB, Tableau, and Power BI, require paid licenses and come with vendor support. Many organizations use both.

One habit links the toolkit to security: never build a SQL query by pasting a user's typed input directly into the query text. That opening allows **SQL injection**, in which an attacker types SQL code that the database then runs. Database libraries offer parameterized queries that keep input separate from the code (Unit 8 covers security).

:::takeaways
- list: ordered and changeable. tuple: ordered and unchangeable. dictionary: key to value lookup with unique keys. set: unique items, unordered.
- Mutable: list, dictionary, set. Immutable: tuple, string. b = a gives the same list a second name; use a.copy() for a separate copy.
- Python indexes from 0; -1 is the last element; slices exclude the stop position; [::-1] reverses.
- range(start, stop) stops before stop. List comprehensions: [expr for x in items if condition].
- Errors: KeyError (missing key), IndexError (position too far), TypeError (wrong types), ValueError (bad value), NameError (undefined name).
- Jupyter notebooks have code and Markdown cells run by a kernel; rerun all cells in order to check reproducibility. pip installs from PyPI, conda manages environments, Anaconda bundles them; virtual environments isolate projects.
- Git tracks versions; GitHub hosts repositories. Clone, commit, branch, merge, push, pull, and pull request are the core actions.
- Languages: Python, R, SQL, Scala (Spark), Java, Julia, JavaScript. Open source is free and community-built; commercial tools are licensed and supported.
:::
