| Harini Suresh and John Guttag, "A Framework for Understanding Sources of Harm throughout the Machine Learning Life Cycle" (EAAMO '21, 2021), "identifies seven distinct potential sources of downstream harm in machine learning": historical bias (harm even when data are perfectly measured and sampled, because the world as it is or was is unfair; example: word embeddings associating "nurse" with women and "engineer" with men); representation bias (the development sample under-represents part of the population; example: about 45% of ImageNet images were taken in the United States, 1% in China and 2.1% in India); measurement bias (features or labels are poor proxies for the target, or are measured differently across groups; example: "arrest" used as a proxy for "crime" in risk assessment); aggregation bias (a one-size-fits-all model for groups that should be treated differently; example: tweets whose emojis and hashtags carry local meanings); learning bias (modeling choices such as the objective amplify disparities; example: pruned or compact models amplifying disparities on underrepresented groups); evaluation bias (benchmark data do not represent the use population, and aggregate metrics hide subgroup underperformance; example: darker-skinned women were only 7.4% and 4.4% of the Adience and IJB-A benchmarks); deployment bias (a model is used differently from the problem it was built to solve; example: risk tools built to predict reoffending used "off-label" to help set sentence length). | https://ar5iv.labs.arxiv.org/html/1901.10002 (arXiv 1901.10002) | 2026-11-02 |

| OWASP LLM01 Prompt Injection (OWASP Gen AI Security Project): "A Prompt Injection Vulnerability occurs when user prompts alter the LLM's behavior or output in unintended ways"; "Direct prompt injections occur when a user's prompt input directly alters the behavior of the model"; "Indirect prompt injections occur when an LLM accepts input from external sources, such as websites or files"; jailbreaking is "a form of prompt injection where the attacker provides inputs that cause the model to disregard its safety protocols entirely"; inputs "can affect the model even if they are imperceptible to humans" (examples include hidden instructions in web pages and images); RAG and fine-tuning: "research shows that they do not fully mitigate prompt injection vulnerabilities." Mitigations: constrain model behavior; define and validate expected output formats; implement input and output filtering; enforce privilege control and least privilege access; require human approval for high-risk actions; segregate and identify external content; conduct adversarial testing and attack simulations. | https://genai.owasp.org/llmrisk/llm01-prompt-injection/ | 2026-11-02 |
| OWASP LLM06:2025 Excessive Agency: "the vulnerability that enables damaging actions to be performed in response to unexpected, ambiguous or manipulated outputs from an LLM"; root causes are excessive functionality (extensions with capabilities the application does not need), excessive permissions (access rights beyond what the task requires) and excessive autonomy (high-impact actions without independent verification or user approval). Example: a mail assistant that only needs to read mail also has send functions, and a malicious email uses prompt injection to make it forward sensitive messages. Mitigations: minimize extensions and their functions, least privilege (for example read-only scopes), human-in-the-loop approval for high-impact actions, authorization enforced downstream, avoid open-ended extensions such as generic shell access. | https://genai.owasp.org/llmrisk/llm062025-excessive-agency/ | 2026-11-02 |
| OWASP LLM05:2025 Improper Output Handling: "insufficient validation, sanitization, and handling of the outputs generated by large language models" before they reach downstream components; exploitation "can result in XSS and CSRF in web browsers as well as SSRF, privilege escalation, or remote code execution on backend systems"; example: "LLM-generated SQL queries are executed without proper parameterization, leading to SQL injection." Mitigations: "Treat the model as any other user, adopting a zero-trust approach"; validate responses before they reach backend functions; encode model output shown to users; "Use parameterized queries or prepared statements for all database operations involving LLM output." | https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/ | 2026-11-02 |
| OWASP LLM04:2025 Data and Model Poisoning: occurs "when pre-training, fine-tuning, or embedding data is manipulated to introduce vulnerabilities, backdoors, or biases"; backdoors "may leave the model's behavior untouched until a certain trigger causes it to change," creating "the opportunity for a model to become a sleeper agent." Prevention includes tracking data origins and transformations (provenance, data version control), vetting data vendors, sandboxing and anomaly detection, red teaming, and monitoring training loss and behavior. | https://genai.owasp.org/llmrisk/llm042025-data-and-model-poisoning/ | 2026-11-02 |
